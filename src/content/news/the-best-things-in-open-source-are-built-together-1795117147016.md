<h2 id="h-replica-a-new-open-source-design-harness" class="wp-block-heading">Replica, a new open-source design harness</h2>



<p class="wp-block-paragraph">In 2025, <a href="https://github.blog/open-source/maintainers/what-to-expect-for-open-source-in-2026/">60% of the top</a> growing open source projects were AI focused. At GitHub, it is no different. A few weeks ago, GitHub&rsquo;s design team introduced <a href="https://github.com/github/replica">Replica</a>, which considers the role of designers in the era of AI and focuses on reinforcement learning. Replica started as an internal project, but it proved to be so useful that our design team shared the tool so developers and designers everywhere could also benefit.</p>



<blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow">
<p class="wp-block-paragraph">GitHub Replica does a lot of reinforcement learning. It&rsquo;s an open source design harness to enable you to do the kind of things you hope to do in prototyping playground</p>
<cite>John Maeda, CVP GitHub &amp; CoreAI Design</cite></blockquote>



<p class="wp-block-paragraph">With Replica, anyone can create AI-generated prototypes within their design system and refine them side-by-side with GitHub Copilot. You can also publish prototypes to a Replica Hub to collaborate with teammates, receive comments, and iterate.</p>



<p class="wp-block-paragraph">With reinforcement learning top of mind, the system learns what good looks like from each interaction and from the comments on the prototypes; it gets better over time. Because Replica is open source, you can hack it and adapt it to fit your teams&rsquo; products and workflows however you see fit.</p>



<h2 id="h-a11y-framework-a-new-open-source-accessibility-framework" class="wp-block-heading">A11y Framework, a new open-source accessibility framework</h2>



<p class="wp-block-paragraph">Developers pushed code changes to GitHub <a href="https://github.blog/news-insights/octoverse/octoverse-commits-pushes-reach-new-highs-in-2026-as-developers-build-with-agents/">17.9 billion times</a> in the last year, more than 2024 and 2025 combined. Commits across all repo types (public and private) climbed even faster to 34.3 billion, more than three times where they stood two years ago. Merged pull requests more than tripled to 1.3 billion over the same period, an average of 3.5 million a day. AI has helped us all build faster. With this volume, and more to be expected, we must keep accessibility top of mind so that the code that is being shipped is accessible to all.</p>



<blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow">
<p class="wp-block-paragraph">As the home for all developers, we want every developer to feel welcome and to be able to contribute to the future of global software development using everything GitHub has to offer.</p>
<cite>Ed Summers, GitHub Head of Accessibility</cite></blockquote>



<p class="wp-block-paragraph">The Open Source Accessibility Framework, created in collaboration with external contributors from the disability and accessibility communities, launched last month. It helps make accessibility an inherent part of how projects are created. It is an accountability model with four phases so developers can turn projects and accessibility goals into public, trackable progress. A core component of this is the new <code>ACCESSIBILITY.md</code> file, a file now visible on repository overview pages, giving a project one durable place to explain its accessibility goals, contributor expectations, supported environments, known limitations, and process for reporting barriers. <a href="https://github.blog/open-source/maintainers/accessibility-statements-now-have-a-home-on-github/">Read more about the <code>ACCESSIBILITY.md</code> file.</a></p>
