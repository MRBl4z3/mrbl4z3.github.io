<html><body><p class="wp-block-paragraph">Developers pushed code to GitHub 17.9 billion times in the past 12 months, more than in 2024 and 2025 combined.</p>



<p class="wp-block-paragraph">Behind that number are developers building what interests them and what their communities need. In Nepal, one developer <a href="https://github.com/nirajbhusal/rasuwa-flood-bulletin">built a flood bulletin on GitHub Pages</a> with verified information on roads, rescue, weather, and power. It has since grown into <a href="https://github.com/nirajbhusal/gati-alerts">Gati</a>, a Nepali-first relay of official disaster alerts that runs on GitHub Pages and Actions. Elsewhere, developers at NASA&rsquo;s Jet Propulsion Laboratory are creating <a href="https://github.com/nasa/spacewasm">software designed to run programs aboard spacecraft</a>, and fans <a href="https://github.com/crosspoint-reader/crosspoint-reader">built open-source firmware that lets people customize their e-readers</a>. Curiosity, aimed in every direction, at a scale GitHub hasn&rsquo;t seen before.</p>



<p class="wp-block-paragraph">That growth happened quickly. Partway through the year, activity on GitHub bent sharply upward, just as agents went from something developers were trying out to something they were working alongside. Developers picked from more models than ever and built in industries we are highlighting in this report for the first time, from health care to agriculture.</p>



<p class="wp-block-paragraph">Octoverse is our chance to step back and look at the whole picture. This year, that picture is bigger than ever. Here is what stood out most:</p>



<ul class="wp-block-list">
<li><strong>More AI, more of everything.</strong> Among repositories created this year, the average repo with an agent configuration file logged eight times as many commits as the average new repo without one.</li>



<li><strong>As of September, developers start more than 40% of pull requests with an agent.</strong> In March, it was 17%. For a growing share of work, the first move is now directing an agent, and review is how developers shape what comes back.</li>



<li><strong>Developers move fast on model choice.</strong> In September, 61% of GitHub Copilot users used more than one model, and requests spread across general purpose, deep reasoning and planning, and fast and lightweight models</li>



<li><strong>Builders are showing up from every field.</strong> This year, for the first time, we&rsquo;re sharing our view of public repositories by industry. Repos serving mining, construction, health care, and agriculture have each grown several times over since 2022.</li>
</ul>



<p class="wp-block-paragraph">Underneath it all, AI models and the harnesses built around them have advanced over the past year, and developers have more to choose from. Growth is moving quickly: one year into last year&rsquo;s five-year developer growth projections, every country we projected has already closed at least a fifth of its distance to 2030, and our own forecasting models no longer agree on where it will go next.</p>



<h2 id="h-the-year-developers-set-a-new-pace" class="wp-block-heading">The year developers set a new pace</h2>

<p class="wp-block-paragraph">This year was all about momentum. Developers pushed code changes to GitHub 17.9 billion times in the past 12 months, more than 2024 and 2025 combined. Commits across all repo types (public and private) climbed even faster to 34.3 billion, more than three times where they stood two years ago. Merged pull requests more than tripled to 1.3 billion over the same period, an average of 3.5 million a day.</p>



<p class="wp-block-paragraph">Agents were one of the tools developers leaned on hardest this year, pulling them deeper into daily work. Among repos created this year, the average repo with an agent configuration file logged eight times as many commits as the average new repo without one, sign that individuals and teams building with agents from day one are moving at a markedly different pace.</p>



<p class="wp-block-paragraph">Developers also relied on automations to keep projects moving. GitHub Actions ran a job 1,440 times every second this year. This equals 124 million times a day and is more than three times last year&rsquo;s total. Developers merged more than 30 million Dependabot pull requests to keep dependencies current and reduce the use of known vulnerabilities, about double 2025&rsquo;s pace.</p>

<p class="wp-block-paragraph">Our telemetry shows activity climbing steadily from January, then surging around June, as if developers everywhere saw new possibilities at once. Right around then, a cluster of industry-wide shifts landed: better underlying models, the harnesses and tools built around them, and the agents running on both. Agents moved from single-session tools to persistent ones that could track progress across days and orchestrate other specialized agents. Just as important, agents began making extensive use of the cloud, executing work remotely as well as on local machines.</p>



<figure class="wp-block-image size-large"><img data-recalc-dims="1" decoding="async" height="576" width="1024" src="https://github.blog/wp-content/uploads/2026/10/Octoverse2026_BlogSpotlight_2.jpg?resize=1024%2C576" alt="Line chart titled &ldquo;GitHub activity accelerated through 2026,&rdquo; comparing monthly activity with September 2025 (1&times;). <p class="wp-block-paragraph">This momentum is showing up both in brand-new repos and from developers who have been building for years. From June onwards, about 55% of all commits came from brand new repositories. But plenty more commits came from developers who&rsquo;ve been around a while: developers who pushed code in the past 12 months have been on GitHub for an average of 36 months, and of those who opened a pull request in August, more than 75% pushed code in September. They are also branching out: the average developer now works across 10% more repositories than they did a year ago.</p>



<p class="wp-block-paragraph">That staying power shows up in open source too. Public contributions soared to 2.5 billion in 2026, more than double last year&rsquo;s total (1.12 billion). Behind those numbers are developers who keep showing up, like <a href="https://github.com/kinlane">@kinlane,</a> who made more than 1 million contributions across his public repositories using agentic workflows to keep a machine-readable catalog of public API information current. Another example is <a href="https://github.com/kim-em">@kim-em</a>, who made more than 178,000 contributions while maintaining mathlib, which is a community library of computer-checked mathematics. <a href="https://github.com/andig">@andig</a>, a maintainer of the open source EV charging controller and home energy management system <a href="https://github.com/evcc-io/evcc">evcc</a>, contributed over 21,000 times.</p>



<p class="wp-block-paragraph">These are just a few examples of the work millions of developers do every day. To all the developers doing work like this and beyond: we see you, and we&rsquo;re glad you&rsquo;re building.</p>



<h2 id="h-developers-are-building-from-more-places" class="wp-block-heading">Developers are building from more places</h2>



<p class="wp-block-paragraph">Behind every number in this report is a developer. GitHub now serves more than 225 million of them, and the community is growing around the globe. The United States (38.3 million) and India (32 million) remain the two largest developer communities, and each added more than 10 million developers this year. Brazil added 3.28 million developers on GitHub this year, the third most of any country.</p>

<p class="wp-block-paragraph">One year in, growth is strong against last year&rsquo;s projection, and projecting the next five years is getting harder. We ran more than 40 forecasting models forward to 2031, time-series and regression models built on historical sign-up and usage data, each assuming a different pace of growth. About half call for &ldquo;extreme&rdquo; growth, with developer counts on GitHub more than tripling by 2031. Just under half call for &ldquo;substantial&rdquo; growth, doubling to tripling. Only three models expect anything close to modest, under 2x growth.</p>

<p class="wp-block-paragraph">This year, it also means more fields, including industries we haven&rsquo;t measured before.</p>



<p class="wp-block-paragraph">We&rsquo;re sharing our view of public repositories by industry using the North American Industry Classification System (NAICS), which sorts economic activity into sectors. A language model classified random samples of public repositories created each year from 2022 to 2026, assigning each to the industry it serves based on its name, description, topics, and README. We also tracked two signals: whether a repository mentions AI, and whether an agent opened a pull request against it.</p>



<p class="wp-block-paragraph">The two signals do not always move together. In administrative and support services, mining, health care, and agriculture, more than four in 10 repositories mention AI, yet agent-opened pull requests are rare, less than 3 percent. Construction breaks that pattern. About a quarter of its repositories mention AI, but about 9 percent have agent-opened pull requests, the highest share of any sector, with manufacturing next.</p>

Professional, scientific, and technical services rose from fourth to second place among all industries, behind only information. Agriculture, forestry, fishing and hunting climbed two spots, and finance and insurance and health care and social assistance each moved up one. <p class="wp-block-paragraph">Behind these sector shifts are people who know their fields, now using AI coding agents to build. For example, in manufacturing, a small team built a way to <a href="https://github.com/tracefinity/tracefinity">turn a photo of your tools into a custom-fit, 3D-printable drawer organizer</a>. A research lab in health care made it easier for scientists to <a href="https://github.com/rendeirolab/wsidata">analyze huge digital scans of tissue samples</a>, the kind pathologists study to understand disease. In Copenhagen, a university lab built a <a href="https://github.com/sbhattlab/PlayClass">pipeline that classifies video of chickens at play, from frolicking to worm chasing</a>. A University of Waikato energy center built a <a href="https://github.com/waikato-ahuora-smart-energy-systems/OpenPinch">toolkit that helps industrial plants find heat they can reuse</a>, and Bulgaria&rsquo;s digital ministry open-sourced a <a href="https://github.com/midt-bg/sigma">portal where anyone can trace who won a public contract and for how much</a>. For writers, a novelist built a <a href="https://github.com/hughhowey/neo">free app that makes a manuscript look like a book as you type</a>. In field after field, the people closest to the problem are building the solution, with agents helping along the way.</p>



<p class="wp-block-paragraph">Professional, scientific, and technical services, which grew about 5 times over its own 2022 baseline and climbed to second place, is the work of researching, engineering, and advising, and open code has long been part of how that work gets done. In biochemistry, the work behind <a href="https://github.com/google-deepmind/alphafold">AlphaFold</a> earned Demis Hassabis and John Jumper a share of the 2024 Nobel Prize in Chemistry. In computer science, <a href="https://github.com/tensorflow/tensor2tensor">Tensor2Tensor</a> accompanied the paper that introduced the Transformer, the architecture behind today&rsquo;s large language models, <a href="https://arxiv.org/abs/1706.03762">&ldquo;Attention Is All You Need.&rdquo;</a> In medicine, <a href="https://github.com/dylanhmorris/sars-cov-2-stability">sars-cov-2-stability</a> held the code and data behind one of the earliest papers on how long the virus survives in the air and on surfaces. In physics, <a href="https://github.com/achael/eht-imaging">eht-imaging</a> was one of two open-source libraries used to reconstruct the <a href="https://arxiv.org/abs/1906.11241">first image of a black hole</a>. A repository has quietly become part of the paper trail behind published research.</p>



<h2 id="h-developers-are-reshaping-their-workflow" class="wp-block-heading">Developers are reshaping their workflow</h2>



<p class="wp-block-paragraph">More developers now begin a pull request by specifying what they want and orchestrating the agents that carry it out. By September 2026, more than 40% of pull requests on GitHub started with an agent&rsquo;s first draft, up from 17% in March. That is 110 million in September alone, about 6x March&rsquo;s volume.</p>



<figure class="wp-block-image size-large"><img data-recalc-dims="1" loading="lazy" decoding="async" height="256" width="1024" src="https://github.blog/wp-content/uploads/2026/10/Octoverse2026_BlogSpotlight_3.jpg?resize=1024%2C256" alt="Three panels highlight agent-generated pull requests: more than 40% of pull requests are agent-generated; agents started 110 million pull requests in September 2026; and agent-generated pull requests grew sixfold in six months." class="wp-image-99769" srcset="https://github.blog/wp-content/uploads/2026/10/Octoverse2026_BlogSpotlight_3.jpg?w=1921 1921w, https://github.blog/wp-content/uploads/2026/10/Octoverse2026_BlogSpotlight_3.jpg?w=300 300w, https://github.blog/wp-content/uploads/2026/10/Octoverse2026_BlogSpotlight_3.jpg?w=768 768w, https://github.blog/wp-content/uploads/2026/10/Octoverse2026_BlogSpotlight_3.jpg?w=1024 1024w, https://github.blog/wp-content/uploads/2026/10/Octoverse2026_BlogSpotlight_3.jpg?w=1536 1536w" sizes="auto, (max-width: 1000px) 100vw, 1000px" /></figure>



<p class="wp-block-paragraph">Agent-started pull requests also more often change multiple files: about 87%, compared with 79% of pull requests without detected agent involvement. They are landing quickly too. In February, 83% of agent-involved pull requests merged within two weeks, a touch behind the roughly 86% for pull requests without detected agent involvement. By September, agent pull requests were at 90%, while the comparison group held at about 86%.</p>

<p class="wp-block-paragraph">Among GitHub Copilot&rsquo;s monthly active users, 55% now use agentic features, up from 35% a year ago. The steepest growth is in the most hands-off mode. Copilot cloud agent, where a developer assigns a task and an agent works on it independently, grew 230% year over year, against 85% for agent chat. Developers still ask agents questions, and increasingly they hand over whole tasks.</p>



<p class="wp-block-paragraph">The willingness to delegate is reflected by the kinds of tasks developers are attempting. Public repositories mentioning interoperability or reverse engineering increased more than 300% year over year, from about 30,000 created in 2025 to more than 130,000 in 2026.</p>

<p class="wp-block-paragraph">Review is where developers shape what comes back, and more tooling is being built for it. <a href="https://docs.github.com/pull-requests/how-tos/stacked-pull-requests?utm_source=octoverse-pr-stacks-docs&amp;utm_medium=blog&amp;utm_campaign=universe-2026">Stacked pull requests</a>, which split related work into smaller changes that are easier to review in sequence, launched as a preview on July 30, and more than 264,000 developers had used them by September. Usage of AI-assisted code review and GitHub Advanced Security both grew more than 90% year over year. The platform also helps secure that work: push protection, which screens for exposed secrets such as API keys and passwords, ran 5.8 billion scans this year, nearly four times 2025&rsquo;s pace. Developers are investing in how they review code.</p>



<h2 id="h-model-choice-moves-at-developer-speed" class="wp-block-heading">Model choice moves at developer speed</h2>



<p class="wp-block-paragraph">Developers match models to the work they hand to their agents. In September 2026, 61% of GitHub Copilot users who selected a model themselves used more than one model across their sessions, up from 50% four months earlier.</p>



<p class="wp-block-paragraph">The lineup is growing too: developers on paid GitHub Copilot plans used 29 distinct models in May and 47 in September, and no single model carried more than 25% of requests that month. Some model decisions come down to cost and familiarity. Developers weigh price and functionality against need and may lean toward providers they already trust.</p>



<figure class="wp-block-image size-large"><img data-recalc-dims="1" loading="lazy" decoding="async" height="256" width="1024" src="https://github.blog/wp-content/uploads/2026/10/Octoverse2026_BlogSpotlight_5.jpg?resize=1024%2C256" alt="Three panels show GitHub Copilot usage in September 2026: 61% of users used more than one model; paying users used 47 distinct models; and the top model accounted for 25% of requests." class="wp-image-99772" srcset="https://github.blog/wp-content/uploads/2026/10/Octoverse2026_BlogSpotlight_5.jpg?w=1921 1921w, https://github.blog/wp-content/uploads/2026/10/Octoverse2026_BlogSpotlight_5.jpg?w=300 300w, https://github.blog/wp-content/uploads/2026/10/Octoverse2026_BlogSpotlight_5.jpg?w=768 768w, https://github.blog/wp-content/uploads/2026/10/Octoverse2026_BlogSpotlight_5.jpg?w=1024 1024w, https://github.blog/wp-content/uploads/2026/10/Octoverse2026_BlogSpotlight_5.jpg?w=1536 1536w" sizes="auto, (max-width: 1000px) 100vw, 1000px" /></figure>



<p class="wp-block-paragraph">To see how developer choices spread, we grouped the models used in GitHub Copilot by what they are built for: deep reasoning and planning, general purpose, and fast and lightweight. We then looked at where requests went, counting only activity where a developer explicitly selected a model. That leaves out cases where GitHub Copilot picks the model (<a href="https://docs.github.com/copilot/concepts/models/auto-model-selection?utm_source=octoverse-auto-model-selection-docs&amp;utm_medium=blog&amp;utm_campaign=universe-2026">auto model selection</a>), GitHub and Microsoft staff usage, background utility models, duplicate requests used for monitoring and testing, and requests made with a developer&rsquo;s own API key.</p>



<p class="wp-block-paragraph">We found that out of every 100 developer-selected requests, 38 went to general purpose models, 37 to deep reasoning and planning models, and 25 to fast and lightweight models. Developers spread their choices across models and functionality, and about 25% of requests go to a fast model.</p>



<figure class="wp-block-image size-large"><img data-recalc-dims="1" loading="lazy" decoding="async" height="576" width="1024" src="https://github.blog/wp-content/uploads/2026/10/Octoverse2026_BlogVisual_2.jpg?resize=1024%2C576" alt="Grid of 100 developer-selected GitHub Copilot requests, excluding the auto model: 37 use deep reasoning and planning models (pink), 38 use general-purpose models (gray), and 25 use fast, lightweight models (green). <p class="wp-block-paragraph">To see how those choices shift, we looked at them as a time series over the past three months, tracking request share alongside how many developers tried each model and how many kept coming back. Three patterns stand out:</p>



<ul class="wp-block-list">
<li><strong>New releases are used heavily before most developers have tried them.</strong> In their first weeks, most new models take a larger share of requests than the portion of developers who have tried them. Early adopters use a model heavily before the rest follow.</li>



<li><strong>Developers keep a model in rotation after leaning on it less.</strong> When a model&rsquo;s share of requests falls, the share of developers still using it falls more slowly</li>



<li><strong>Developers blend kinds of models.</strong> Requests spread across all three groups, and few developers stay with any one kind for long.</li>
</ul>



<p class="wp-block-paragraph">Taken together, the spread across kinds of models points to a lot of choosing: a lineup that keeps growing, a best fit that shifts from one task to the next, and all three kinds of models held in rotation. Many developers also let GitHub Copilot do some of it. In September 2026, 63% of paying GitHub Copilot developers used <a href="https://github.blog/changelog/2026-09-14-configure-cost-and-quality-in-copilot-auto-model-selection/">auto model selection</a> at least once, letting Copilot pick the model for the task.</p>



<p class="wp-block-paragraph">Planning, implementing, and checking a change each place different demands on a model, in capability, speed, and cost. <a href="https://github.blog/ai-and-ml/github-copilot/project-hydrafusion-frontier-quality-via-multi-model-orchestration/">Project HydraFusion</a>, began as a research preview of model orchestration, matching models to each step of that work. In the CLI and the GitHub Copilot app, it routed almost 60,000 sessions. That work is now generally available as <a href="https://docs.github.com/copilot/concepts/models/copilot-fusion?utm_source=octoverse-fusion-docs&amp;utm_medium=blog&amp;utm_campaign=universe-2026">GitHub Copilot Fusion</a>, which brings model orchestration together with auto model selection and chooses the right model for each step behind the scenes.</p>

<h2 id="h-language-choice-has-new-influence" class="wp-block-heading">Language choice has new influence</h2>



<p class="wp-block-paragraph">Language choice has long reflected what developers want to build, what their teams know, and what existing systems require. This year&rsquo;s data raises the question of whether a fourth influence is emerging: the language an agent picks when a developer doesn&rsquo;t specify one.</p>



<p class="wp-block-paragraph">Last year, we reported that TypeScript had overtaken Python and JavaScript to become the most used language on GitHub by contributors. That order held in 2026, with TypeScript first, Python second, and JavaScript third. The pace picked up. From September 2025 to September 2026, TypeScript added 3.62 million monthly contributors, Python 3.23 million, and JavaScript 1.82 million, the largest gains among the top 10 languages. Rust grew fastest by percentage among the top languages, doubling in the past year.</p>



<p class="wp-block-paragraph">Our forecasts extend recent trends: TypeScript and Python near 13 million monthly contributors each by September 2027, JavaScript at 7.4 million, and every other language in the top 10 below about 2.2 million.</p>

We charted each language&rsquo;s community growth over the past year against the share of its merged pull requests with detected AI involvement, with bubbles roughly sized to show the size of each language&rsquo;s community. <p class="wp-block-paragraph">The repository data adds another angle. Among repositories created in 2026, TypeScript was the primary language in 35% of those with an observed agent signal, compared to 24% without one. For repositories created before 2026, the gap was similar: 27% with an agent signal, versus 17% without. That suggests developers who work with agents gravitate toward languages where agent output is easier to check. Developers who know exactly what they want still specify the language. But when they leave the choice open, agents appear to favor a narrower set of languages, TypeScript chief among them.</p>



<h2 id="h-what-is-capturing-developer-attention" class="wp-block-heading">What is capturing developer attention</h2>



<p class="wp-block-paragraph">This year, we split the fastest-growing and most-engaged projects on GitHub into two groups: community and independent repositories, and single-vendor or product-led ones. Community and independent projects are foundation-governed, broadly maintained, or led by an individual without a clear commercial sponsor. Single-vendor and product-led projects are open source or source-available and often take substantial community contributions, but strategic control sits with one company.</p>



<p class="wp-block-paragraph">Read together, the two lists show a division of labor. The community side is mostly the foundation underneath everything else: inference engines like vLLM, SGLang, and llama.cpp, frameworks like PyTorch, languages and runtimes like Rust and CPython, and platforms like Home Assistant and Godot. The vendor side is mostly the tools developers work with directly: coding agents, editors, and the orchestration around them. Contributors are showing up for both layers. The growth list also includes places built to welcome newcomers, like first-contributions and is-a-dev/register, where many developers make their first pull request.</p>

<h2 id="h-what-doesn-t-change" class="wp-block-heading">What doesn&rsquo;t change</h2>



<p class="wp-block-paragraph">As part of our research this year, we also tracked the emoji developers used most in their repositories. Across every industry we looked at, the rocket &#128640; topped the list, by a wide margin. A fitting symbol for a year of momentum. Developers on GitHub covered more ground this year: more code, more countries, and more industries than we&rsquo;ve ever measured. None of that activity changes who decides what the code should do. Someone still has to come up with the idea, whether it&rsquo;s <a href="https://github.com/gem/oq-engine">software that assesses earthquake risk</a>, <a href="https://github.com/opentermsarchive/engine">an open record of how online services change their terms and privacy policies</a>, or <a href="https://github.com/JuliusBrussee/caveman">an agent skill that makes an AI answer like a caveman to save on words</a>. And someone still has to decide whether it works, whether it belongs, and whether it&rsquo;s good.</p>



<p class="wp-block-paragraph">What did change is how much easier it is to take an idea from a weekend thought to something real.</p>



<p class="wp-block-paragraph">The tools will keep changing, and new industries will keep showing up in places we didn&rsquo;t expect. What a developer chooses to build, and who they build it for, is still theirs to decide. Rocket emoji and all.</p>

<h2 id="h-glossary" class="wp-block-heading">Glossary</h2>



<ul class="wp-block-list">
<li><strong>Agent configuration file:</strong> A repository file that sets up or directs an AI coding agent. Also called an AI configuration file or agentic file. Repositories without one may still use AI.</li>



<li><strong>Agent signal:</strong> An observed sign of agent involvement in telemetry, such as an agent-opened pull request. It is a floor, since not all agent use may be detected.</li>



<li><strong>Agent-started pull request:</strong> A pull request whose first draft came from a coding agent that we can detect.</li>



<li><strong>Auto model selection:</strong> A GitHub Copilot setting where Copilot picks the model for the task.</li>



<li><strong>Commit:</strong> A saved snapshot of changes to a repository.</li>



<li><strong>Contributions:</strong> Activity events: commenting on a commit, issue, pull request, or discussion; creating a gist, issue, pull request, or discussion; pushing code; and reviewing a pull request. Each push counts once, however many commits it holds. Open-source contributions are contributions to public and open source repositories.</li>



<li><strong>Contributors:</strong> GitHub users with at least one contribution in the period.</li>



<li><strong>Copilot cloud agent:</strong> A GitHub Copilot feature where a developer assigns a task and an agent works on it independently.</li>



<li><strong>Dependabot:</strong> GitHub&rsquo;s automated tool that finds outdated or vulnerable dependencies and opens pull requests to update them.</li>



<li><strong>Developer-selected request:</strong> A model request where we proxied the developer chose the model. It excludes auto model selection, staff usage, duplicate monitoring and testing requests, background utility models, and requests made with a developer&rsquo;s own API key.</li>



<li><strong>GitHub Actions job:</strong> A single unit of work in a GitHub Actions workflow.</li>



<li><strong>GitHub Advanced Security:</strong> GitHub&rsquo;s suite of application security features, including code scanning, secret scanning, and dependency review.</li>



<li><strong>NAICS:</strong> The North American Industry Classification System, the standard sector taxonomy used this year to classify public repositories by industry.</li>



<li><strong>Project HydraFusion:</strong> A GitHub research preview of model orchestration, which plans a task across models, such as one drafting, another reviewing, and a more capable one stepping in when needed. Now generally available as GitHub Copilot Fusion.</li>



<li><strong>Push:</strong> Sending saved changes to GitHub. One push can carry many commits.</li>



<li><strong>Stacked pull requests:</strong> A review workflow that splits related work into a sequence of smaller pull requests that are reviewed in order.</li>
</ul>



<h2 id="h-methodology" class="wp-block-heading">Methodology</h2>



<ul class="wp-block-list">
<li><strong>Scope and window.</strong> The Octoverse year runs October 1, 2025 to September 30, 2026, inclusive. Unless noted, metrics include public and private repositories. Industry, open-source contribution, and open-source project figures are public only. Prior years: 2024 and 2025 figures are recalculated on the same definitions and window, so they may differ from earlier reports, which covered public activity and a September 1 to August 31 window.</li>



<li><strong>Pushes, commits, and contributions.</strong> A push sends one or more commits to GitHub. Contributions count each push once, so commit totals can exceed contribution totals. Actions are counted in jobs, not minutes. Open-source contributions (2.5 billion) are public.</li>



<li><strong>Filtering.</strong> Contributor and contribution counts exclude spam-flagged accounts, staff, and bots where identifiable.</li>



<li><strong>Geography and projections.</strong> Developers are mapped to countries by self-reported location, with a 100-developer publication threshold. Octoverse 2025 published 2030 totals, not annual targets. Progress is net developers added from September 2025 to September 2026 as a share of the distance from each country&rsquo;s published 2025 count to its 2030 projection.</li>



<li><strong>Languages.</strong> Contributors are distinct accounts each month that took part through pushes, pull requests, issues, reviews, or comments, attributed to each repository&rsquo;s primary language (Linguist). An account can count in several languages. This follows the Octoverse 2025 method. Forecasts cover the top 10 languages by average monthly participation and project to September 2027 (mean shown).</li>



<li>The <strong>language bubble chart</strong> compares growth in monthly participating accounts between September 2025 and September 2026 with the share of merged pull requests with detected AI involvement. Bubble size reflects community size.</li>



<li><strong>Top countries by pushes to public repositories, adjusted by profile location.</strong> Pushes from each country were summed across the Octoverse year. To adjust for biases caused by VPN usage, LLM classification was used to extract the ISO 3166-1 alpha-2 code from the profiles of GitHub users who contributed pushes during this period, which were then used to construct ratios of ISO 3166-1 alpha-2 codes based on profile location vs. ISO 3166-1 alpha-2 codes based on IP address. These ratios were then used to weight the pushes from each country.</li>



<li><strong>Industry.</strong> Public repositories created 2022 to 2026 were sorted into NAICS sectors by a fine-tuned multilingual embedding model using name, description, topics, and README, from random samples per year. AI mentions and agent-opened pull requests (detectable agents only) were flagged as separate signals. Sector and AI-mention shares can be related because both read the same text. Shares are estimates.</li>



<li><strong>Open-source rankings.</strong> Repositories are classed as community or single-vendor by who holds strategic control. &ldquo;Fastest-growing&rdquo; ranks by the absolute year-over-year increase in distinct contributing accounts. &ldquo;Most engaged&rdquo; blends a repository&rsquo;s rankings for stars, forks, and distinct pull request and issue creators. Forked repositories are excluded from both lists.</li>



<li><strong>Model choice.</strong> Figures cover GitHub Copilot and count developer-selected requests only. They exclude auto model selection, staff usage, duplicate monitoring requests, background utility models, and requests made with a developer&rsquo;s own API key. Each model needs at least 1,000 weekly active users to count. Models are grouped by what they are built for, with examples listed alphabetically by provider:</li>



<li><strong>Deep reasoning and planning:</strong> Claude Opus 5.5, GPT 5.5.</li>
